# Turbo 项目构建工具 · 界面审查稿

交付文件：`design/turbo-build-demo.html`。纯 HTML/CSS/JavaScript，双击即可用浏览器打开，无外部字体、图标、网络或构建依赖。服务器信息只在页面展示，所有操作使用本地模拟，不发送 SSH 请求。

## 已核实的数据

对当前服务器只读检查得到 4 个 `apps/` 一级业务目录，每个都有独立 `.git`、`package.json`，其 Git 根目录分别属于对应业务仓库。项目名、当前分支、下拉框内本地分支均使用本次检查快照。

| 业务目录 | 包名 | 当前分支 | 根目录构建命令 |
| --- | --- | --- | --- |
| web-admin | @repo/admin | dev | pnpm build:dev:admin |
| web-bms | @repo/bms | ref-FeeItemConfig | pnpm build:dev:bms |
| web-copilot | @repo/copilot | dev | pnpm build:dev:copilot |
| web-tms | @repo/tms | feat/optimize-waybill-dashboard | pnpm build:dev:tms |

根目录 `build:dev` 确实存在并调用 Turbo 构建全部项目。另有 `build:dev:multichannel` 脚本，但当前 `apps/` 没有对应目录，故不将其展示为可选仓库。

## 功能与交互

| 编号 | 区域 | 行为 |
| --- | --- | --- |
| REQ-01 | 连接与扫描 | 打开页面自动模拟扫描；保存连接也自动扫描。手动重新扫描保留仍存在的项目选择。扫描失败保留上次列表和选择；修改服务器或根目录先清空旧仓库、选择与任务，再扫描。 |
| REQ-02 | 仓库列表 | 每行业务内容保持单行，显示业务名、实际当前分支与行内构建状态、目标分支，以及依次排列的切换、Pull、打包、查看日志。目录通过业务名悬停提示查看，长分支省略并可悬停查看全文。展开目标分支时自动刷新该仓库的分支列表，移除行内刷新按钮；弹层显示刷新中或刷新失败及重试入口。刷新保留仍有效的目标选择，失效的目标选择清空；选择分支后仍需点击切换才改变实际分支。支持鼠标、Enter/空格/方向键展开，以及列表方向键、Home/End、Enter 选择、Escape 关闭。现有操作语义为仓库目录内 git fetch/checkout/pull。 |
| REQ-03 | 构建选择 | 支持一个、多个和全部项目。搜索不会丢失隐藏项目的选择；表头复选框只作用于当前筛选结果。底部“全选”选择整个扫描范围；“清空选择”取消所有勾选。 |
| REQ-04 | 统一批量构建 | 搜索栏右端依次放置“重新扫描”和“批量构建”，两个按钮均为纯文字，构建按钮不显示数量；选择数量在卡片底部展示。未选择或操作中禁用构建。部分项目按目录去掉 web- 前缀匹配真实存在的 build:dev:* 脚本。选中全部仓库时，确认并执行一条 pnpm build:dev。行内“打包”只创建该仓库的计划，不覆盖已有多选。 |
| REQ-05 | 构建与日志 | 确认弹窗展示仓库和各自当前分支、命令。开始后锁定仓库操作和扫描；日志查看保持可用。右侧仅显示日志与来源信息，支持自动滚动和清空显示。失败重试入口放在左侧卡片底部。全部命令失败只认定整批失败，不虚构单项目成功结果。 |
| REQ-06 | 桌面布局 | 移除品牌导航、头像和网站式大页眉。窗口采用左仓库、右日志的等高双面板，面板内部滚动；底部显示轻量运行状态。构建计划仅在确认弹窗展示，不再保留右侧计划卡或底部任务区。清理卡片、弹窗、空状态和底部的解释性文案，仅保留字段名称、实际数据、操作和必要状态。 |
| REQ-07 | 每个进程的日志 | 每个业务行增加“查看日志”，尚无打包任务时禁用，有任务后打开该业务最近一次任务对应的进程日志。日志来源下拉框可切换会话、历次批次和各个进程；历史日志不会被重试覆盖。每个进程显示命令、批次与进程编号、构建分支快照、执行状态和耗时；未启动的任务明确显示尚未启动，不生成虚构 PID。 |
| REQ-08 | 状态联动 | 构建行依次显示准备构建、等待构建、正在构建、成功或失败。前序失败后的项目和清理失败涉及的项目显示未执行；日志仍可查看失败原因。扫描保留日志映射，分支切换和 Pull 清除旧构建结果标记但保留历史日志。日志来源切换不修改项目勾选，也不触发打包；查看某个进程时，下一进程启动不会抢走当前日志视图。 |

实际实施时，扫描应校验独立 Git 仓库和 package.json；逐项目命令必须同时存在于根 scripts 中，不能仅通过目录名拼接后盲目执行。缺失脚本等不可用项需展示原因，不允许逐项目构建。根 `build:dev` 的真实范围以 Turbo 工作区配置为准。Demo 的四个项目均已匹配，不制造不存在的异常仓库。

## 本次提出、供审查的执行规则

- 部分项目逐个串行执行，某个失败后停止剩余项目。“重试未完成项目”包含失败和未执行项目，跳过已成功项；确认弹窗重新读取这些项目当前分支。
- 一批任务先校验所有目标仓库的实际分支，再清理一次工作区根目录 `.turbo`。部分项目的后续命令共享本批重新生成的缓存，不在项目之间重复清理。
- 清理失败时整批停止，构建命令均标为未执行。分支操作期间暂停构建；构建期间锁定所有仓库分支操作，避免版本在构建过程中改变。
- Demo 为便于查看多选效果，初始勾选 BMS 与 TMS；正式工具首次进入建议不预选项目。
- 部分项目每个命令对应一个独立进程，查看时只展示该进程输出，并附本批共享的分支校验和缓存清理记录；不混入其他进程的构建输出。全部构建仍是一个 `pnpm build:dev` 进程，所有业务日志按钮指向同一份共享日志，明确标注全部项目共享进程。
- Demo 保留当前页面全部批次与进程的日志，以及最近一批构建的重试信息，刷新页面后重置。清空显示仅隐藏当前视图已有内容，重新选择日志来源可恢复记录。更换连接会清空旧连接的日志和进程映射，防止串用。现有引擎的磁盘日志保留机制由后续桌面实现复用。

## 审查路径与验收

1. AC-01 / REQ-01：打开页面看到自动扫描结束和 4 个仓库；模拟“扫描失败”后重扫，原列表和选择仍保留。
2. AC-02 / REQ-02：给 admin 选择 master，确认其他行不变；点击切换后只更新 admin 当前分支。单行打包弹窗只含该仓库。
3. AC-03 / REQ-03、04：勾选 BMS/TMS，底部显示已选 2 / 4，批量按钮保持纯文字，点击后弹窗显示两条构建命令；选满 4 项后弹窗改为一条 pnpm build:dev。
4. AC-04 / REQ-03：搜索 TMS 后仍保留 BMS 选择；表头取消仅取消可见 TMS；清除搜索后勾选全部可切换统一命令。
5. AC-05 / REQ-05：确认构建后仓库操作锁定，右侧日志出现一次根目录清理和对应命令；全部构建只有一条统一命令。
6. AC-06 / REQ-05：自动验证注入构建失败、清理失败，检查日志和左侧重试入口。BMS 成功、TMS 失败后重试弹窗仅包含 TMS。清理失败后日志不得出现开始构建的记录。
7. AC-07 / REQ-01：更改连接并保存，旧项目和选择清空，自动重新扫描；新列表默认不勾选。
8. AC-08 / REQ-06：1520×900 和 1120×760 桌面窗口左右面板等高且完整可见，批量按钮与搜索框同排，页面不横向或纵向溢出；右侧不含计划和队列标签。设计目标为桌面客户端，最小布局宽度为 1040px。
9. AC-09 / REQ-07、08：初始四个日志按钮禁用；任务开始后可在分支操作锁定时查看日志。BMS 执行期间 TMS 显示等待；查看 BMS 日志后，TMS 开始不会自动切换日志来源。
10. AC-10 / REQ-07：BMS/TMS 批次失败后分别查看，BMS 日志没有 TMS 构建输出，TMS 日志没有 BMS 构建输出；两份均包含共享准备日志。重试 TMS 后仍能通过来源选择查看前一次失败记录。
11. AC-11 / REQ-07：全部构建时四个业务打开同一个共享进程日志；整批失败后四行显示整批构建失败。此前成功的批次仍保持成功和原有输出。
12. AC-12 / REQ-08：选 admin/BMS/TMS 模拟第二个进程失败，admin 成功、BMS 失败、TMS 未执行；TMS 日志注明前序失败且不含启动命令。重试弹窗只含 BMS/TMS，分支切换后使用最新分支。
13. AC-13 / REQ-07：清空进程日志显示后重新选择同一来源，可恢复完整记录；修改连接后来源恢复为会话，四个业务日志按钮恢复禁用。
14. AC-14 / REQ-02：鼠标或键盘展开目标分支时触发刷新，加载期间暂停构建、扫描和其他仓库操作；完成后展示分支选项。刷新失败后可以重试，原有目标选择及实际分支保持不变。再次展开仍会刷新，选择后只更新目标；Escape 关闭并将焦点返回分支按钮。

以上浏览器交互路径已通过 `tmp-verify/verify_turbo_demo.py` 使用独立无窗口 Chrome / Playwright 检查，未移动系统鼠标或切换用户窗口。检查覆盖演示页面行为，不代表 SSH 后端、并发执行或真实构建功能已实现。
