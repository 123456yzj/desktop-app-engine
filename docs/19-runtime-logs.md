# 运行与任务日志

运行时和生成的应用自动保存日志。通用宿主底部提供“日志与任务”“打开日志目录”。`vben-package` 使用右侧日志面板，按当前会话、构建批次或进程选择来源，显示状态和退出码；每个进程包含本批共享准备日志，各进程构建输出独立，全选构建共用一个进程。历史批次在本次会话内保留，完整文件可通过“日志目录”查看。

## 文件位置与生命周期

默认位置：`%LOCALAPPDATA%\DesktopAppEngine\logs\app-<EXE文件名，不含扩展名>\session-<时间戳>-<进程号>-<序号>\`。例如 `vben-package.exe` 使用 `app-vben-package`。应用名中的非 ASCII 字母、数字、横线或下划线替换为下划线，最多取前 80 个字符。主目录创建失败时尝试系统临时目录下的相同结构，回退原因记录为 `log.fallback`。窗口显示实际会话目录，目录按钮打开实际应用日志根目录。

每次启动创建独立会话；`--check` 等命令行模式也生成会话。日志在应用退出后保留，不设自动清理或磁盘大小上限；可关闭应用后按需删除历史会话。窗口保留本次启动最近 64 个任务及尚未结束的任务；更早任务文件仍在磁盘。

| 文件 | 内容 |
| --- | --- |
| `engine.jsonl` | 每行一个 JSON 运行事件：启动、加载、动作调用与错误、命令开始/结束、GUI 运行错误、panic 及正常退出 |
| `task-*/task.json` | 任务 ID、动作/结果目标标签、程序文件名、工作目录、超时、开始时间 |
| `task-*/stdout.log` | stdout 原始字节，读取到输出即写入，无 16 KiB 截断 |
| `task-*/stderr.log` | stderr 原始字节，与 stdout 分开保存 |
| `task-*/result.json` | 任务状态、退出码、错误、结束时间、耗时、结果生成时双流字节数和 `outputComplete` |

命令窗口每条流只保留最近 32 KiB 的预览，按 UTF-8 有损解码；引擎运行事件窗口保留最近 128 条。运行中及日志窗口打开时定期重绘。命令业务 target 的六字段契约保持原定义，仍在任务结束后提交每条流的前 16384 字节，以兼容已有结构化结果解析。

## 动作入口

0.2 动作可以增加 `{"type":"openLogs"}`，例如：

```json
"openLogs": {"steps": [{"type": "openLogs"}]}
```

此步骤无参数，打开宿主日志窗口，不修改业务状态。模块中也可使用。只打开应用内窗口；系统目录窗口仅在用户点击目录按钮时打开。

## 错误与输出边界

启动失败、非零退出、超时和取消均记录任务结果。日志创建或写入失败会在宿主底部显示错误，命令继续执行。panic 日志包含位置、消息和回溯；强制结束进程、断电或系统崩溃无法保证留下结束事件或任务结果。

命令结束后，两条输出管道分别最多等待 100ms。后代进程继承管道或读取发生错误时，`outputComplete=false`，表示结果生成时尚未确认输出完整结束；窗口会提示。尚存活的读取线程仍继续写日志，直到管道关闭或应用退出，结果内字节数为生成时快照。日志文件读取失败也记录为 `command.readFailed`。引擎仅终止直接子进程，不保证远端任务或本地后代停止。

引擎不会自动转储命令参数、业务状态、HTTP 请求体、认证头或解密凭据。命令输出按原样保存，内容由被执行脚本决定；日志不进行秘密值识别或脱敏。任务元数据中的程序名、工作目录、动作标签会被记录。

## 验证方式

日志落盘位于 `src/services/logging.rs`，通用查看器位于 `src/renderer/logs.rs`，业务预览由工作台控制器组织。实际任务应检查原始 stdout/stderr、result.json 和 outputComplete，以确认退出结果与输出完整性。

## SSH 工作台退出码修复

`vben-package` 使用登录 Bash，以加载远端构建所需的环境。一些服务器的 `.bash_logout` 会执行 `clear_console -q`，在无终端 SSH 会话中返回非零；如果退出时仍启用 `set -e`，可能把原本成功的项目操作变成失败。

远端 EXIT 处理现在先保存真实操作退出码，再执行 `set +e`，报告阶段与当前分支，最后用保存的退出码退出。真正的 fetch、checkout、pull 或构建失败仍返回原始非零码。日志新增 `[vben] stage=... exit=...` 和客户端操作开始/结束记录，即使命令静默失败也能定位阶段；仓库路径无效时报告 repository 阶段，不返回错误目录的当前分支。失败提示指向实时日志，诊断摘要保留最近 80 行。

生成命令的阶段与参数引用、真实 SSH 和登录环境行为需在目标环境验证。

## 打包前清理缓存

打包在仓库验证与实际分支核对通过后，进入 `clean-turbo` 阶段，记录清理开始并执行 `rm -rf -- ./.turbo`，成功后进入 `build` 阶段执行 `pnpm build:dev:tms`。路径固定为当前项目根目录下的 `.turbo`；不存在时正常继续，删除失败时由 `set -e` 停止，结果保留清理退出码并记录失败阶段。分支不一致时在清理前停止，显式退出前关闭 errexit，保证登录 Bash 的登出脚本不会把退出码 4 改写为 1。

共享清理与逐进程构建由 `src/bin/vben-package/turbo_build/backend.rs` 生成，准备阶段和构建阶段分别执行。
