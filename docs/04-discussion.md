## 问答摘要

1. 问：想自定义界面，通过 SSH 获取数据和执行命令。
   答：需要界面编辑、数据源、动作与服务器连接。
2. 问：软件放在 Windows 上。
   答：目标是 Windows 桌面应用。
3. 问：有没有现成项目？
   答：研究了 Node-RED、Windmill 等；独立应用导出需要额外处理。
4. 问：想用 Rust 或 GUI。
   答：可复用 Rust GUI，自研描述和执行层。
5. 问：SSH 性能开销如何？
   答：复用持久连接；主要开销取决于命令和频率，细节后续处理。
6. 问：需求和原型谁先？
   答：先核心需求，再原型验证与修正。
7. 问：最终需要产出独立桌面应用。
   答：区分制作工具和生成应用，生成应用无需编辑器运行。
8. 问：有能生成桌面应用的工具吗？
   答：讨论了 VisualNEO Win、B4J、Slint，未确认完整满足全部目标的工具。
9. 问：描述、元素关联和打包如何定义？
   答：用版本化描述、稳定 ID、状态绑定和事件动作建立契约。
10. 问：制作 App 分哪些步骤？
    答：创建、界面、连接、数据、动作、关联预览、生成。
11. 问：菜单等复杂界面如何处理？
    答：公共框架、导航、多页面和嵌套容器。
12. 问：先做基本引擎生成 EXE。
    答：先验证基础组件、绑定、动作及打包。
13. 问：技术不限制 Rust，有哪些基础项目？
    答：评估 Qt Quick/QML、Avalonia、Slint。
14. 问：能用 Rust 重写引擎吗？
    答：可写应用描述引擎，并复用 GUI；用户选择这条路线并授权实施。
15. 问：在父目录新建文件夹，实施前分文档记录方向和步骤。
    答：工作位置改为本目录，先完成本套简短记录。

## 总结

先做基本引擎与示例 EXE，再逐步增加 SSH、复杂页面及低代码编辑器。
