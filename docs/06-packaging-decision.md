# 分发决策：固定运行时 + 应用描述包

日期：2026-10-12；2026-10-13 增加 0.2 Dashboard。状态：采用 A。运行时独立支持 0.1/0.2，分发方式不变。

## 目标与比较

编辑器应能一键导出，修改界面不触发 Rust 编译；客户机不安装 Rust、源码或制作工具。

| 方案 | A：固定运行时 + app.json / 资源包 | B：描述编译进 EXE |
| --- | --- | --- |
| 修改界面 | 修改描述并复制文件 | 修改内嵌描述后重新编译 |
| 编辑器导出 | 复用已构建 runtime，复制描述即可 | 生成端必须具备完整 Rust 构建环境 |
| 客户机 | 不需要 Rust，分发整个应用目录 | 不需要 Rust，分发 EXE |
| 版本管理 | 运行时与描述分别更新，协议版本严格校验 | 描述和运行时绑定于一次构建 |
| 代价 | 必须保留同目录描述，文件可由使用者修改 | 每个应用都要编译，产物更新成本较高 |

选择 A 作为正式导出形态。平台先构建一次运行时；同协议下导出不同应用不编译 Rust。
B 保留为开发期快捷方式：内嵌 hello.json 用于直接启动、快速验证引擎，不是编辑器导出的默认方式。

## 当前应用包

```text
应用名/
  应用名.exe   # release 运行时的原样副本
  app.json     # 协议 0.1 或 0.2 描述，原样复制
  README.txt   # 一页使用说明
```

运行时与描述均不依赖工作目录。加载顺序为显式 `--app FILE`、EXE 同目录的 `app.json`、内嵌开发示例。
显式描述错误，或同目录描述存在但不可读/非法，立即报错，不回退。只有同目录描述不存在才使用内嵌示例。
无法定位 EXE 或最终示例不可用时也给出中文错误；失败退出 2，`--check` 成功退出 0。
当前内嵌示例是编译期必需文件，通常始终可用；最终兜底仍走解析和校验。

`scripts/package.ps1 -Description FILE -Output DIR [-Name NAME]` 只复制已有 release 运行时，不编译也不联网。
运行时位置优先使用 `CARGO_TARGET_DIR/release`，否则为项目 `target/release`。不得使用旧 dist 副本。
名称默认取描述的 app.name，非法 Windows 名称需通过 -Name 覆盖；已有目标应用目录拒绝覆盖。
生成包后自动从包外工作目录执行 `--check`，检查退出码，失败保留产物用于诊断并返回 2。

## 边界与后续

客户机需要 Windows 中文系统字体和 OpenGL 驱动。主题、字体和动作语义保持不变。
协议 0.1 尚无资源引用，因此本次只交付 app.json，不增加资源格式或加载规则。
后续如有图片等资源，应单独定义包内相对路径契约；本次不实现编辑器、SSH、安装包、签名和自动更新。
验证结果与环境限制见 docs/03-implementation-plan.md。
